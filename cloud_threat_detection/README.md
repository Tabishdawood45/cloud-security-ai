# AI-Powered Cloud Threat Detection and Automated Response System

A complete end-to-end Python implementation built for the bachelor thesis:

> **Role of Artificial Intelligence and Automation in Cloud Security: Design and Implementation of an AI-Based Threat Detection and Automated Response Framework.**

The project simulates a realistic cloud activity stream, trains two
complementary machine-learning models, detects suspicious behaviour,
generates automated alerts, and visualises everything in a clean Flask
dashboard.

---

## Key facts at a glance

* **Main model:** `IsolationForest` — unsupervised. It is the model used
  for all live anomaly detection and for generating every alert in the
  response engine.
* **Comparison baseline only:** `RandomForestClassifier` — supervised.
  It is trained and reported **purely as a benchmark** for the thesis
  evaluation chapter. It is **not** used to generate alerts.
* **Dataset:** **fully synthetic**, generated by `generate_logs.py`. No
  real production logs are used.
* **Class balance:** the dataset intentionally contains **20 % suspicious
  events**, which is **far higher than a real production environment**
  (where attacks are typically well under 1 %). This ratio was chosen on
  purpose for testing and evaluation — see the section below.

---

## Important note about the dataset

The dataset used in this project is **fully synthetic** and is generated
by `generate_logs.py`. **No real production logs are involved** — this
is deliberate so that the code can be reproduced freely without
exposing sensitive data.

The generator intentionally produces:

* **10,000 events in total**
* **80% normal events** (`label = 0`, `attack_type = normal`)
* **20% suspicious events** (`label = 1`) split across four attack families:
  `brute_force`, `data_exfiltration`, `privilege_escalation`, `geographic_anomaly`

The 20% suspicious ratio is **higher than what would be seen in a real
production environment**, where suspicious activity is usually well
under 1%. The ratio was chosen on purpose so that:

1. Both classes are well represented during model training,
2. The dashboard has enough alerts to look populated in screenshots, and
3. Evaluation metrics (Precision / Recall / F1 / Confusion Matrix) are
   numerically stable and easy to discuss in the thesis.

The random seed `random_state = 42` is fixed in every module so that
the dataset, model training, and reported metrics are fully
reproducible across runs.

A clean Python 3.10+ environment is recommended.

```bash
# 1. (Optional but recommended) create a virtual environment
python -m venv venv
source venv/bin/activate          # macOS / Linux
venv\Scripts\activate             # Windows

# 2. Install dependencies
pip install -r requirements.txt
```

## Running the pipeline

The scripts are designed to be run **in order**, each one consuming the
output of the previous step.

```bash
python generate_logs.py        # 1. Generate 10,000 synthetic log records
python train_model.py          # 2. Train Isolation Forest + Random Forest
python detect_threats.py       # 3. Run anomaly detection on the dataset
python response_engine.py      # 4. Generate alerts (CSV + SQLite)
python evaluate_model.py       # 5. Compute metrics & save charts
python app.py                  # 6. Launch the Flask dashboard
```

When `app.py` is running, open <http://127.0.0.1:5000> in a browser to
view the dashboard.

## What each module does

| # | File | Purpose |
|---|------|---------|
| 1 | `generate_logs.py`   | Creates `data/cloud_activity_logs.csv` containing 10,000 synthetic cloud-activity events with a known `label` (0 = normal, 1 = suspicious) and an `attack_type` column. Suspicious rows reproduce four realistic attack families: `brute_force`, `data_exfiltration`, `privilege_escalation` and `geographic_anomaly`. |
| 2 | `train_model.py`     | Encodes categorical features, scales numerical ones, trains an `IsolationForest` (main model, unsupervised) and a `RandomForestClassifier` (comparison baseline). All artefacts are persisted under `models/`. The `attack_type` column is excluded from the feature set to avoid label leakage. |
| 3 | `detect_threats.py`  | Loads the trained Isolation Forest, predicts anomalies for every event, adds `prediction`, `anomaly_score`, `threat_level` and `recommended_action` columns (preserving `attack_type`), and saves `data/detection_results.csv`. |
| 4 | `response_engine.py` | Reads detection results, generates an alert for every suspicious event (including its `attack_type`), and persists them both to `data/alerts.csv` and to the SQLite database `cloud_security.db`. |
| 5 | `evaluate_model.py`  | Compares predictions against the ground-truth labels, reports Accuracy / Precision / Recall / F1 / Confusion Matrix, and saves four PNG charts: `threat_level_distribution.png`, `attack_type_distribution.png`, `confusion_matrix.png`, `model_metrics.png`. |
| 6 | `app.py` + `templates/dashboard.html` | Flask web app that surfaces all of the above: KPI cards, threat-level breakdown, latest alerts (with attack-type pills), top suspicious users, four evaluation charts and the metrics table. |

## Dataset schema

| Column | Description |
|--------|-------------|
| `event_id`           | Unique identifier (e.g. `E000001`) |
| `timestamp`          | When the event occurred |
| `user_id`            | User who performed the action (`U0001` … `U0500`) |
| `ip_address`         | Source IPv4 address |
| `country`            | Country of origin |
| `resource_accessed`  | Cloud resource (e.g. `/iam/roles`) |
| `action_type`        | `read`, `write`, `download`, `delete`, … |
| `failed_logins`      | Failed login attempts in the session |
| `session_duration`   | Session length in seconds |
| `data_download_mb`   | Volume of data downloaded |
| `admin_action`       | Whether an admin-level action was performed (`Yes`/`No`) |
| `risk_score`         | Pre-computed risk score 0 – 100 |
| `attack_type`        | One of: `normal`, `brute_force`, `data_exfiltration`, `privilege_escalation`, `geographic_anomaly` |
| `label`              | Ground truth: `0` = normal, `1` = suspicious |

The `attack_type` column is metadata used for analysis and dashboard
visualisation only — it is **not** used as an input feature when
training either model (that would leak the label).

## Models

* **Isolation Forest — *main model***. This is the primary detector used
  for inference and for every alert generated by the response engine. It
  is unsupervised, which matches the realistic case where production
  cloud logs do not come with reliable labels.
* **Random Forest Classifier — *comparison baseline only***. It is
  trained on the same labelled data so that the thesis can quantify how
  much an unsupervised approach gives up versus a supervised one. The
  Random Forest is **not** used for alert generation; it appears only in
  the evaluation chapter and the dashboard's metrics table.

Both models are evaluated on the same dataset against the ground-truth
labels and their results are shown side-by-side on the dashboard.
